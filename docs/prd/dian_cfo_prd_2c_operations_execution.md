# 디안 CFO 대시보드 PRD
## 카테고리 2c: 운영 실행 (Operations & Execution)

**문서 버전**: v0.1 (1차 초안)  
**기준 일자**: 2026년 5월 4일  
**카테고리 위치**: 디안 대시보드 7대 영역 중 #2c ― 운영 실행  
**참고 도서**: 없음 (v1.0 보강 + 디안 비즈니스 특성 반영)

---

## 1. 개요

### 1.1 목적
본 카테고리는 **디안의 일상 운영(거래·제품·재고·샘플·납품)을 효율적으로 처리**하고, 그 결과 데이터를 다른 카테고리(목표·계획·영업·마케팅·측정·의사결정)에 정확히 송출하는 인프라 역할을 한다.

다른 카테고리들이 "전략·분석·결정"을 다룬다면, 본 카테고리는 그 전략이 매일 실제로 일어나는 곳 ― 디안의 가장 일상적이고 반복적인 운영 영역이다.

### 1.2 배경
**v1.0과의 관계**:
v1.0의 다섯 메뉴 중 다음 세 메뉴가 본 카테고리의 직접 보강 대상이다.
- 일일결산 → ① 일일 운영 대시보드
- 거래 관리 → ② 거래 입력·추적
- 제품 관리 → ③ 제품·재고·샘플 관리

추가로 v1.0의 **공문 작성** 메뉴는 ⑤ 문서 자동화로 진화한다.

**다른 카테고리에서 이미 활용 중인 v1.0 메뉴** (본 카테고리에서는 데이터 소스로만 작동):
- 거래처 관리 → #2a 영업 전략 (② 거래처 360 뷰)
- 미수금 관리 → #3 측정·분해 (⑨ 미수금 ― 추후 상세)
- 비용 관리 → #3 측정·분해 (③ 자원 인수분해)
- 분석/시뮬레이션 → #3, #4
- AI CFO 자문 → #4 의사결정 (③ 4단계 워크플로우의 의사결정 보조)

### 1.3 디안 비즈니스의 운영 특성

본 카테고리 PRD는 다음 디안 비즈니스 특성을 직접 반영한다.

1. **24셀 세그먼트 운영**: 6직업군 × 4제품군 각 셀의 운영 패턴이 다르다 (#2a 카테고리 정의)
2. **4티어 포지셔닝**: 저가·중가·프리미엄·럭셔리 라인의 운영 정책이 다르다 (#4 카테고리 정의)
3. **시즌 사이클**: SS·FW 두 시즌 + 인테리어 트렌드 사이클
4. **샘플·스왓치 운영**: 디자이너에게 보내는 샘플 추적 (반환/분실/재구매 전환) ― 디안 고유 영역
5. **다양한 납기 패턴**: 인테리어 프로젝트(긴 사이클) vs 업소용 천갈이(빠른 회전)
6. **반복 거래 vs 프로젝트 거래**: 브랜드 가구의 정기 매입 vs 프로젝트 가구의 1회성 견적

### 1.4 카테고리의 위치
본 카테고리는 디안 대시보드 7대 영역 중 **#2c 영역**이며, **데이터 인프라 허브** 역할을 한다.

- **출력 (모든 다른 카테고리에 데이터 송출)**:
  - 매출·거래 데이터 → #3 측정·분해
  - 거래 활동 → #2a 영업 전략 (활동 다이어리 자동 등록)
  - 재고 회전·죽은 재고 → #3 측정·분해 + #4 의사결정
  - 시즌별 운영 패턴 → #2b 마케팅 (콘텐츠 캘린더 인풋)
  - 납기 KPI → #1 목표·계획

- **입력**:
  - 가격 정책 → #4 의사결정 (확정 가격표가 ② 거래 입력에 자동 적용)
  - 마케팅에서 발생한 신규 거래 → #2b의 드림 100·콘텐츠에서 컨택 → 본 카테고리에서 첫 거래

## 2. 핵심 원칙

1. **v1.0 보존**: 기존 v1.0 메뉴의 데이터·기능은 그대로 유지. 사용자가 익숙한 흐름이 깨지지 않도록.
2. **자동 데이터 송출**: 운영 데이터는 직원이 따로 입력하지 않아도 자동으로 다른 카테고리에 흘러간다.
3. **세그먼트·티어 인식**: 모든 거래·제품·샘플은 세그먼트(24셀)와 티어(4단계)에 자동 매핑되어 분석 가능.
4. **디안 고유 영역 강화**: 샘플 추적·시즌 사이클·납기 관리는 일반 ERP에 없는 디안 특화 기능.
5. **자동화 우선**: 반복 거래·견적 작성·발주는 가능한 한 자동화. 사람은 예외 상황에 집중.
6. **시간 차원 보존**: 일/주/월/12주 모든 시간 단위로 데이터 조회 가능.

## 3. 사용자 시나리오

### 3.1 페르소나

**페르소나 A: 운영 담당자 (또는 영업 담당자가 겸임)**
- 매일 거래 입력 + 일일결산
- 샘플 발송·추적
- 재고 모니터링
- 발주·납품 일정 관리

**페르소나 B: 영업 담당자**
- 견적 작성 + 거래 등록
- 자기 거래처의 운영 상태 모니터링

**페르소나 C: 대표 (CEO)**
- 일일 운영 결과 확인 (① 대시보드)
- 운영 KPI 모니터링 (⑥)
- 예외 상황 의사결정 (납기 지연·재고 부족 등)

### 3.2 핵심 사용자 여정

**여정 1: 매일 아침 일일결산 (운영 담당자)**
1. ① 일일 운영 대시보드 진입
2. 어제 거래 누계·매출·미수금 확인
3. 오늘 발송할 샘플·납품 목록 확인
4. 오늘 들어올 발주·입고 확인
5. 이상 알림 (재고 부족·납기 지연 등) 처리

**여정 2: 새 거래 입력 (영업 또는 운영)**
1. 거래처 검색 (#2a 거래처 360에서 자동 가져옴)
2. ② 거래 입력 화면 ― 제품 선택 + 수량 + 가격
3. 가격은 #4의 거래처별 정책 자동 적용
4. 세그먼트·티어 자동 분류
5. 거래 등록 → 다른 카테고리에 데이터 자동 송출

**여정 3: 디자이너가 샘플 요청 (영업)**
1. ③ 제품·샘플 관리에서 요청 제품 검색
2. 샘플 발송 등록 (디자이너·날짜·반송 예정일)
3. 자동으로 #2a 영업 활동 다이어리에 "샘플 발송" 활동 등록
4. 14일 후 자동 후속 알림 ("샘플 반송·구매 전환 확인")
5. 결과에 따라 거래로 전환 또는 재고 복원

**여정 4: 시즌 전환 시점 (대표 + 운영)**
1. ③ 제품 관리에서 SS → FW 전환 모드
2. 죽은 재고 자동 식별 (12주 이상 회전 없음)
3. 처분 의사결정 (할인 / 보관 / 처분)
4. 신규 시즌 라인업 등록 → #4 가격 결정 워크플로우 자동 시작 (③ 4단계 프로세스)

**여정 5: 거래처 발주서 송부 (자동화)**
1. ④ 발주·납품 워크플로우에서 발주 트리거 발생 (재고 임계값·정기 발주 일정·고객 주문)
2. ⑤ 문서 자동화가 발주서·견적서·계약서 자동 생성
3. 담당자가 검토·승인
4. 거래처에 자동 발송
5. 입고 시 ② 거래 자동 업데이트

- **B. 워크플로우** (자동화): ④, ⑤
- **C. KPI**: ⑥

### 4.1 ① 일일 운영 대시보드

**목적**: v1.0 일일결산 메뉴를 보강하여, 매일 아침 운영 상황을 한눈에 파악할 수 있도록 한다.

**주요 컴포넌트**:
- (상단) 어제 운영 결과 카드:
  - 어제 매출 (전일·전주·전년 대비)
  - 어제 거래 건수
  - 어제 신규 거래처
  - 어제 입금·미수 변화
  - 어제 발송 샘플 수

- (중단) 오늘 액션 카드:
  - 오늘 발송할 샘플 (디자이너별)
  - 오늘 납품 일정 (납기 임박 알림)
  - 오늘 입고 예정
  - 오늘 견적 마감 (#2a 영업과 연동)

- (중단) 이번 주 누계 (월요일~오늘):
  - 매출 누계 (12주 목표 대비 진행률)
  - 거래 누계
  - 신규 거래처 누계
  - 활동량 (#2a 영업 KPI와 연동)

- (중단) **이상 알림 영역**:
  - 재고 부족 경고 (특정 SKU 임계값 미만)
  - 납기 지연 위험
  - 샘플 미반송 (반송 예정일 경과)
  - 미수금 증가 알림
  - 시즌 전환 임박 (SS→FW 또는 FW→SS)

- (하단) 빠른 액션 버튼:
  - 새 거래 입력 → ②
  - 새 샘플 발송 → ③
  - 견적서 작성 → ⑤

**핵심 인터랙션**:
- 모든 카드 클릭 → 상세 페이지로 드릴다운
- 이상 알림 클릭 → 해결 워크플로우 자동 시작
- 회의실 모드 (월요일 WAM 미팅에서 큰 화면)

**시각 요소**:
- KPI 카드 그리드
- 어제·오늘·이번주 시간 분할
- 알림 신호등 (긴급·주의·정상)

**권한**:
- 운영·영업 담당자: 본인 관련 데이터
- 대표·임원: 전체

---

### 4.2 ② 거래 입력·추적

**목적**: v1.0 거래 관리를 보강. 모든 거래의 입력·수정·추적을 일원화하고, 자동으로 다른 카테고리에 데이터 송출.

**주요 컴포넌트**:
- (상단) 거래 입력 폼:
  - 거래처 검색 (자동 완성, #2a 거래처 마스터)
  - 거래 유형: 신규 거래 / 재구매 / 정기 발주
  - 제품 선택 (다중 선택, ③ 제품 마스터)
  - 수량·단위 입력
  - 가격: #4의 거래처별 정책 자동 적용 + 수정 시 사유 기록
  - 납품 일정
  - 결제 조건 (현금·30일·60일·90일)
  - 메모

- (중단) **자동 분류 (사용자 확인)**:
  - 세그먼트 자동 추정 (24셀 중 어디?)
  - 티어 자동 추정 (저가·중가·프리미엄·럭셔리)
  - 사용자가 확인·수정 가능

- (중단) 거래 목록 (최근 거래 + 필터):
  - 필터: 거래처·제품·세그먼트·티어·기간·상태
  - 정렬: 최신순·금액순·납기순
  - 상태 표시: 견적 → 확정 → 출하 → 납품 → 입금 (단계별 색상)

- (중단) **거래 상세** (선택 시):
  - 거래 정보 (위 입력 항목)
  - 단계 변경 이력
  - 관련 활동 (#2a 영업 다이어리에서 자동 표시)
  - 관련 샘플 (③에서 자동 표시)
  - 관련 문서 (⑤에서 자동 표시 ― 견적서·계약서·세금계산서)
  - 마진 자동 계산 (단가 − 변동비, #3과 연동)

- (하단) 거래 후속 자동화:
  - 거래 등록 시 → #2a 활동 다이어리 자동 등록
  - 거래 등록 시 → #3 매출·자원 데이터 자동 업데이트
  - 납품 일정 → ④ 워크플로우 자동 등록
  - 결제 조건 → 미수금 추적 자동 시작

**핵심 인터랙션**:
- 가격 변경 시 사유 입력 강제 (#4 가격 결정 이력에 자동 기록)
- 거래 단계 변경 시 자동 알림 (담당자 + 거래처)
- 다중 거래 일괄 입력 (CSV 임포트)

**시각 요소**:
- 거래 목록 테이블 (필터·정렬)
- 거래 단계 진행 표시
- 거래 상세 패널

**권한**:
- 영업 담당자: 본인 거래처 거래 입력·수정
- 운영 담당자: 모든 거래 처리 권한
- 대표·임원: 전체

### 4.3 ③ 제품·재고·샘플 관리

**목적**: v1.0 제품 관리 보강. 디안의 다양한 제품 라인 + 재고 + **샘플·스왓치** 운영을 통합 관리.

**주요 컴포넌트**:

**파트 A: 제품 마스터**
- 제품 카탈로그 (모든 SKU):
  - SKU 코드, 제품명, 사진
  - 사업부 분류 (가구·벽면·소품·윈도우)
  - 세그먼트 적합도 (24셀 매트릭스에서 어느 셀에 적합한가)
  - 티어 분류 (저가·중가·프리미엄·럭셔리)
  - 시즌 (상시·SS·FW·한정판)
  - 핵심 스펙 (소재·구성·내구성 Martindale·방염·방오·폭·중량 등)
  - 단위 변동비 (원가)
  - 정상가 + 거래처 등급별 가격 (#4 ⑤와 연동)

**파트 B: 재고 관리**
- 실시간 재고 현황:
  - SKU별 현재 재고
  - 재고 회전율 (이 SKU가 평균 몇 일 만에 팔리는가)
  - 죽은 재고 식별 (12주 이상 회전 없음 자동 알림)
  - 시즌 종료 임박 SKU 알림
- 재고 가치 분석:
  - 총 재고 가치
  - 사업부별·티어별 분해
  - 죽은 재고 가치 (회계상 손실 위험)
- 재고 임계값 + 자동 발주:
  - 임계값 미만 시 자동 ④ 워크플로우 트리거

**파트 C: 샘플·스왓치 추적** (디안 고유 영역)
- 샘플 발송 등록:
  - 누구에게 (디자이너·스튜디오·가구사)
  - 어떤 샘플 (SKU·수량)
  - 언제 발송, 반송 예정일
  - 목적 (프로젝트 검토·트렌드 파악·신규 제안)
- 샘플 추적:
  - 현재 외부에 나간 샘플 목록
  - 반송 예정일 경과 알림
  - 샘플 → 거래 전환률 (디자이너별·SKU별)
- 샘플 ROI:
  - 샘플 1건당 평균 매출 기여
  - 샘플 비용 vs 만든 매출 (#3 자원 인수분해와 연동)
- 스왓치 라이브러리:
  - 디지털 스왓치북 (사진+스펙+컬러 코드)
  - 디자이너에게 공유 가능한 링크 자동 생성
  - 다운로드 추적 (어느 디자이너가 어떤 SKU를 봤는지)

**핵심 인터랙션**:
- 새 SKU 등록 시 #4 ① 포지셔닝 매트릭스 자동 등록 워크플로우 시작
- 재고 임계값 도달 시 자동 발주 트리거 (④ 워크플로우)
- 샘플 발송 시 #2a 활동 다이어리 자동 등록
- 죽은 재고 식별 시 #4 의사결정 카테고리에 처분 옵션 자동 제안

**시각 요소**:
- 제품 카탈로그 그리드 (사진 중심)
- 재고 히트맵 (회전율·죽은 재고 시각화)
- 샘플 타임라인 (외부 샘플 추적)
- 디지털 스왓치북

**권한**:
- 운영·영업 담당자: 제품·재고·샘플 조회 + 본인 영역 입력
- 대표·임원: 전체 + 죽은 재고 처분 결정
- 마케팅: 디지털 스왓치북 활용 (콘텐츠 제작)

### 4.4 ④ 발주·납품·배송 워크플로우

**목적**: 반복 거래·정기 발주·납품 일정을 자동화. 사람은 예외 상황에만 개입.

**주요 컴포넌트**:

**파트 A: 발주 자동화** (디안 → 공급사)
- 자동 발주 트리거:
  - 재고 임계값 미만 (③에서 자동)
  - 정기 발주 일정 (예: 매주 월요일)
  - 거래처 주문 누적이 임계값 도달
- 발주 워크플로우:
  - 시스템이 발주 제안 → 담당자 검토·수정·승인 → 공급사 송부
  - ⑤ 문서 자동화로 발주서 자동 생성
  - 입고 예정일 추적

**파트 B: 납품 워크플로우** (디안 → 거래처)
- 납품 일정 캘린더:
  - 가로축: 날짜
  - 세로축: 거래처
  - 셀: 납품 예정 (수량·금액)
  - 색상: 상태 (확정·출하 준비·출하 중·납품 완료)
- 납기 추적:
  - 납기 임박 알림 (D-3, D-1, 당일)
  - 납기 지연 위험 자동 식별 (재고 부족·물류 문제)
  - 24셀 세그먼트별 평균 납기 사이클 (예: 업소용은 2일, 인테리어 프로젝트는 7-14일)

**파트 C: 배송 추적**
- 배송 업체 연동
- 배송 상태 추적
- 거래처에 자동 알림 (출하·도착)

**파트 D: 예외 처리**
- 납기 지연 시 ― 자동으로 거래처 알림 + 사유·신규 일정 기록
- 클레임·반품 처리 워크플로우
- 분실·손상 처리

**핵심 인터랙션**:
- 발주서·견적서 → ⑤ 문서 자동화 호출
- 납품 완료 시 ② 거래 단계 자동 전환
- 거래처 알림은 자동 발송 (이메일·문자·카톡)

**시각 요소**:
- 발주·납품 캘린더
- 워크플로우 단계 표시
- 예외 알림 영역

**권한**:
- 운영 담당자: 작성·승인·예외 처리
- 영업 담당자: 본인 거래처 납품 모니터링
- 대표: 전체 + 예외 의사결정

### 4.5 ⑤ 문서 자동화 (v1.0 공문 작성 진화)

**목적**: v1.0 공문 작성을 진화. 견적서·발주서·계약서·세금계산서·통지문 등 모든 비즈니스 문서를 자동 생성.

**주요 컴포넌트**:
- (상단) 문서 유형 선택:
  - **견적서**: 거래 제안 시
  - **발주서**: 디안 → 공급사
  - **거래확인서**: 거래 확정 후
  - **납품서**: 납품 시
  - **세금계산서**: 입금 후 (회계법인 연동 가능)
  - **계약서**: 연간 계약·럭셔리 라인 등
  - **통지문**: 가격 변경·시즌 전환·이벤트 안내
  - **공문**: v1.0 기능 보존

- (중단) 자동 생성 워크플로우:
  - 거래·발주 데이터에서 자동 채움 (이름·주소·금액·제품·일정)
  - 거래처 정보 자동 호출 (#2a 거래처 마스터)
  - 가격 정보 자동 호출 (#4 가격 결정)
  - 디안 브랜드 템플릿 자동 적용 (로고·서명·연락처)

- (중단) 문서 템플릿 라이브러리:
  - 24셀 세그먼트별 맞춤 템플릿
    - 인테리어 프로젝트용 견적서 (긴 사이클·디테일 중심)
    - 업소용 천갈이 견적서 (간결·즉납 중심)
    - 럭셔리 라인 계약서 (격조·희소성 강조)
  - AI 도구 통합으로 톤·문구 자동 조정

- (중단) 문서 발송·서명:
  - PDF 자동 생성
  - 거래처에 이메일 자동 발송
  - 전자 서명 워크플로우 (계약서·중요 문서)
  - 발송·열람·서명 추적

- (하단) 문서 보관·검색:
  - 모든 발송 문서 자동 보관
  - 거래처별·기간별 검색
  - 거래 상세에서 자동 연결 (② 거래 입력)

**핵심 인터랙션**:
- ② 거래 입력 시 → "거래확인서 발송" 원클릭
- ④ 발주 워크플로우에서 → "발주서 자동 생성"
- 가격 변경 시 → 거래처별 통지문 자동 작성 (#4 의사결정)

**시각 요소**:
- 문서 유형 카드 그리드
- 템플릿 미리보기
- 발송·열람 추적 패널

**권한**:
- 영업·운영 담당자: 문서 생성·발송
- 대표: 계약서·중요 문서 승인
- 모든 문서: 디안 브랜드 가이드 자동 적용 (#1·#2b 카테고리와 일관성)

### 4.6 ⑥ 운영 KPI 대시보드

**목적**: 운영의 효율성·정확도·자동화율을 측정. **운영 자체의 부가가치**를 가시화.

**핵심 KPI**:

**KPI 1: 운영 사이클 타임**
- 견적 요청 → 견적 발송: 평균 시간
- 거래 확정 → 출하: 평균 시간  
- 출하 → 납품: 평균 시간
- 납품 → 입금: 평균 시간
- 24셀 세그먼트별 사이클 (각 셀의 표준 사이클과 비교)

**KPI 2: 정확도**
- 거래 입력 정확도 (수정·취소 비율)
- 납기 준수율 (% 정시 납품)
- 견적 정확도 (견적 vs 실제 거래 차이)
- 재고 정확도 (시스템 vs 실제 차이)

**KPI 3: 자동화율**
- 자동 처리된 발주 vs 수동 발주
- 자동 생성된 문서 vs 수동 작성
- 자동화로 절약된 시간 추정 (인건비 환산)

**KPI 4: 샘플 효율성** (디안 고유)
- 샘플 발송 → 거래 전환률
- 샘플 1건당 평균 매출 기여
- 디자이너별 샘플 효율
- SKU별 샘플 효율

**KPI 5: 재고 효율성**
- 평균 재고 회전율
- 죽은 재고 비율
- 재고 자본 효율 (재고 가치 vs 매출)

**KPI 6: 운영 부가가치**
- 운영 인력 1명당 처리 거래 건수
- 운영 인력의 시간당 부가가치 (#3 카테고리와 연동)
- 운영 비용 vs 매출 비율

**주요 컴포넌트**:
- (상단) 6개 KPI 카드 (12주 목표 대비 진행률)
- (중단) 시간별 추세
- (중단) 24셀 세그먼트별 비교
- (하단) 개선 추천:
  - "자동화 가능한 반복 작업 N개 발견"
  - "이 SKU의 재고 회전이 평균 대비 X% 느림 ― 처분 검토 필요"
  - "이 거래처의 사이클이 표준보다 Y일 길다 ― 원인 분석"

**핵심 인터랙션**:
- KPI 카드 클릭 → 상세 분석
- 추천 액션 → 해당 페이지로 자동 이동
- 12주 KPI는 #1 목표·계획에 자동 송출

**시각 요소**:
- KPI 카드 그리드
- 사이클 타임 시계열
- 24셀 세그먼트 매트릭스

**권한**:
- 운영 담당자: 본인 영역 KPI
- 대표·임원: 전체 + 비교 분석

- **이메일·SMS·카톡 API**: 자동 알림 발송
- **AI 도구**: 문서 톤 조정·자동 문구 생성

## 9. v1.0 마이그레이션 계획

### 9.1 v1.0 메뉴 활용 매핑

| v1.0 메뉴 | 본 카테고리에서의 활용 | 변경 사항 |
|---|---|---|
| **일일결산** | ① 일일 운영 대시보드 | 그대로 유지, 시각화·자동화 강화 |
| **거래 관리** | ② 거래 입력·추적 | 그대로 유지, 세그먼트·티어 자동 분류 추가 |
| **제품 관리** | ③ 제품·재고·샘플 | 그대로 유지, 샘플 추적·스왓치 라이브러리 추가 |
| **공문 작성** | ⑤ 문서 자동화 | 진화 ― 견적서·발주서·계약서·통지문 자동화 추가 |

### 9.2 데이터 보존 원칙

- v1.0의 모든 거래·제품·일일결산·공문 데이터는 **삭제하지 않는다**.
- 본 카테고리는 v1.0 데이터 위에 **메타데이터 (세그먼트·티어·자동 추적)** 를 추가하는 방식.
- 사용자는 v1.0 메뉴 화면에 그대로 접근 가능 (전환 기간).

### 9.3 마스터 데이터 초기 설정

- 기존 모든 제품을 24셀 세그먼트 적합도에 매핑 (1회성)
- 기존 모든 제품을 4티어로 분류 (1회성, #4 카테고리 마스터 데이터와 동일)
- 기존 거래처에 24셀 세그먼트 매핑 (1회성, #2a 카테고리와 동일)
- 자동 발주 임계값 설정 (SKU별)
- 문서 템플릿 디자인 (디안 브랜드 가이드 적용 후)

## 10. 구현 우선순위 (참고)

| Phase | 페이지 | 비고 |
|---|---|---|
| **P0 (1차)** | ① 일일 대시보드, ② 거래 입력 | v1.0 즉시 보강 |
| **P1 (2차)** | ③ 제품·재고·샘플, ⑥ 운영 KPI | 샘플 추적은 디안 고유 영역 |
| **P2 (3차)** | ④ 발주·납품 자동화, ⑤ 문서 자동화 | 자동화 단계 |

**P0 우선순위 근거**:
- v1.0 핵심 메뉴(일일결산·거래)를 빠르게 보강하여 다른 카테고리에 데이터 흐름 시작
- ① ②가 작동하면 #1·#2a·#3 카테고리가 즉시 데이터를 받기 시작

**P1 근거**:
- 샘플 추적은 디안 고유 영역이라 외부 ERP에 없는 가치
- 운영 KPI가 있어야 #1 카테고리의 후행지표가 완성

**P2 근거**:
- 자동화는 시스템 정착 후 점진적 확장
- 처음부터 모든 자동화를 도입하기보다 운영 패턴이 익숙해진 후 자동화

## 11. 미해결 사항 / 추후 결정 필요

### 11.1 대표님 결정 대기

- **배송 업체 연동 범위**: 어느 배송사? API 연동 가능한지?
- **이메일·문자·카톡 자동 알림 정책**: 어디까지 자동, 어디부터 사람 검토?
- **자동 발주 임계값**: SKU별 최소 재고 기준
- **샘플 운영 정책**: 샘플 비용 부담 (무료·유료·반환 시 환불 등), 반환 기한
- **시즌 전환 시점**: SS·FW 전환 캘린더 정의

### 11.2 시범 운영 후 재검토

- 자동화 범위의 적정성 (너무 많으면 통제 불능, 너무 적으면 비효율)
- 샘플 추적 시스템의 디자이너 협조도 (샘플 반환률)
- 24셀 세그먼트 자동 분류의 정확도

### 11.3 다른 카테고리에서 결정될 사항

- 거래처 마스터 데이터 정의 → #2a 영업
- 제품 티어 분류 → #4 의사결정
- 가격 정책 → #4 의사결정
- 미수금 관리 상세 → #3 ⑨ 미수금 별도 PRD

### 11.4 별도 PRD가 필요한 영역

대표님이 이전에 말씀하신 대로, 다음 영역은 본 카테고리 운영 후 별도 상세 PRD가 필요할 수 있다:

- **미수금 관리 상세 PRD** (#3 ⑨에서 자리만 잡고 추후 작성)
- **회계법인 연동 상세 PRD** (외부 세무사와의 데이터 동기화)
- **배송·물류 통합 PRD** (배송사 변경·반품·클레임 워크플로우)
