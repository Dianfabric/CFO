# 카테고리 #8: 팀 공유 (Team Share)

> 디안 CFO 대시보드의 핵심 지표·공지를 슬랙(Slack)으로 자동 공유하는 카테고리.
> 직원·임원이 매일/매주/매달 회사 상태를 동기화 받고, 대표는 1:1로 흩어진 정보 전달 부담을 줄임.

## 1. 개요

소규모 팀이라도 회사 정보가 한 사람(대표)에게 집중되면 다음 문제가 발생:
- 직원이 회사 흐름을 모름 → 의사결정 시 동기·맥락 부족
- 대표가 같은 정보를 반복 전달 (시간 낭비)
- 위기·기회 신호를 직원이 놓침

**해결 방향**: v1.1 시스템에 누적된 데이터를 정기 슬랙 메시지로 자동 발송. 직원은 디안 시스템을 직접 보지 않아도 핵심 흐름을 파악.

## 2. 핵심 원칙

### 2.1 행동 가능한 지표만 공유 (Actionable)
직원이 행동을 바꿀 수 있는 지표만 공유. 단순 통계 X.
- **공유**: 어제 매출, 신규 거래처, 활동량, 12주 목표 진행률
- **비공유**: 1:1 노트, CEO 자기경영 점검, 가격 차별화 정책 상세

### 2.2 동기 부여 + 인정
- 매주 칭찬·축하·하이라이트 자동 포함
- 큰 거래 성사·신규 거래처 확보 즉시 알림
- 12주 목표 달성 시점 마다 축하

### 2.3 권한 위계 보호
| 정보 유형 | 직원 채널 | 임원 채널 | CEO 전용 |
|---|---|---|---|
| 매출 합계 | ✓ | ✓ | ✓ |
| 거래처별 구체 매출 | ❌ | ✓ | ✓ |
| 미수금 합계 | ✓ | ✓ | ✓ |
| 미수금 거래처 명세 | ❌ | ✓ | ✓ |
| 가격 차별화 정책 | ❌ | ✓ | ✓ |
| 1:1 노트·자기경영 점검 | ❌ | ❌ | ✓ |
| AI 모닝 브리핑 | ❌ | ❌ | ✓ |
| 위기 알림 (90일+ 연체 등) | ❌ | ✓ | ✓ |

### 2.4 불필요한 알림 최소화
**알림 피로 경계** — 매일 5분 이내로 읽을 수 있는 분량.
- 일일 메시지: 핵심 지표 4개 + 1줄 코칭
- 주간 메시지: 8개 KPI + 회의 요약
- 월간 메시지: 더 풍부한 분석 (15분 분량)

### 2.5 발송 시각 = 흐름의 일부
- 모닝 브리핑은 **오전 8시** (대표·임원만)
- 일일 팀 메시지는 **오전 9시** (전 직원)
- 주간 메시지는 **월요일 오전 10시** (WAM 직후 또는 직전)
- 월간 메시지는 **매월 1일 오전 10시**

## 3. 지표 카테고리 — 무엇을 언제 공유하는가

### 3.1 일일 (매일 오전 9시, 직원 채널)

```

📊 어제 결과
• 매출 X원 (vs 같은 요일 평균 ±X%)
• 거래 N건 · 활성 거래처 N곳

🎯 오늘 (자동 알림)
• 납기 예정 N건
• 샘플 발송 예정 N건
• {WAM 일정} (월요일만)

🌟 어제 하이라이트
• 신규 거래처: {거래처명} (있을 때만)
• 큰 거래: {거래처} {금액} (1천만+일 때만)

• {대표 작성 공지, 있을 때만}
```

## 4. 페이지 구조 (3개 페이지)

### 4.1 ① 팀 공유 허브 (`/finance/team`)

**목적**: 어떤 메시지가 언제 누구에게 발송되는지 한눈에 보고 미리보기.

**주요 컴포넌트**:
- 발송 상태 카드 (오늘 발송됨 ✓ / 다음 발송 D-X)
- 일일/주간/월간 미리보기 탭 — 실제 발송될 메시지 그대로
- "지금 즉시 발송" 버튼 (테스트용)
- 채널별 설정 링크
- 최근 발송 이력 (성공/실패)

**핵심 인터랙션**:
- 미리보기 → 즉시 발송 (테스트)
- 채널·시각 변경 → 슬랙 설정 페이지로

### 4.2 ② 공지 관리 (`/finance/team/announcements`)

**목적**: 대표가 직원에게 슬랙으로 공유할 공지를 미리 작성·예약.

**주요 컴포넌트**:
- 공지 추가 폼 (제목·내용·발송 일자·중요도)
- 활성 공지 리스트 (예정 발송)
- 발송된 공지 이력
- 즉시 발송 / 다음 일일에 포함 옵션

**필드**:
- title (제목)
- body (본문)
- include_in_daily (일일 메시지에 포함)
- include_in_weekly (주간 메시지에 포함)
- send_immediately (즉시 발송)
- importance (low/normal/important/urgent)
- target_channel (employees/executives/all)
- scheduled_date (발송 예정 일자)
- expires_at (만료 일자)

### 4.3 ③ 슬랙 설정 (`/finance/team/slack`)

**목적**: 슬랙 워크스페이스 연결 + 채널·시각·필터 설정.

**주요 컴포넌트**:
- Webhook URL 입력 (채널별 — 직원/임원/CEO/축하)
- 발송 시각 설정 (일일/주간/월간)
- 필터 토글 (어떤 지표를 포함할지 — 카테고리별 ON/OFF)
- 즉시 발송 테스트 버튼 (각 채널별)
- 발송 활성화 마스터 스위치

## 5. 데이터 모델

### 5.1 핵심 엔티티

| 엔티티 | 핵심 필드 | 비고 |
|---|---|---|
| `team_announcements` | id, title, body, importance, scheduled_date, expires_at, target_channel, sent_at | 대표 공지 |
| `slack_settings` | id (singleton), employees_webhook, executives_webhook, ceo_webhook, daily_time, weekly_time, monthly_time, enabled | 채널·시각 |
| `slack_send_log` | id, target_channel, message_type, payload, sent_at, status, error | 발송 이력·디버깅 |
| `daily_team_digests` | id, digest_date, content, sent_at | 발송된 일일 메시지 보관 (재발송·검토용) |

### 5.2 외부 연동

- **Slack Incoming Webhooks** (가장 단순): 채널마다 webhook URL 발급. POST → JSON 페이로드.
- **OAuth 옵션** (추후): bot token으로 인터랙티브 메시지 (버튼 클릭 → 액션)

## 6. 권한 위계

| 채널 | 받는 사람 | 보호 데이터 |
|---|---|---|
| **직원 채널** (`employees_webhook`) | 마케팅·운영 직원 | 거래처별 매출 ❌, 가격 정책 ❌ |
| **임원 채널** (`executives_webhook`) | CEO + 임원 | 1:1 노트 ❌, 자기경영 ❌ |
| **CEO 채널** (`ceo_webhook`) | CEO 본인만 | 모든 정보 OK |

웹훅 URL은 SUPABASE에 저장하되, **CEO/임원만 편집 가능**(RLS).

## 8. 시각·UX 가이드라인

### 8.1 슬랙 메시지 포맷
- **이모지 활용**: 시각적 구분 (📊 📅 🎯 🌟 ⚠)
- **굵게·이탤릭 활용**: 핵심 숫자·이름 강조
- **블록 구분**: 섹션 사이 빈 줄로 가독성
- **너무 길지 않게**: 일일 5문단 이내, 주간 10문단 이내

### 8.2 시각 정체성
- 디안 브랜드 색상 활용 (주: 어두운 그레이, 강조: 따뜻한 황톤)
- 이모지는 미니멀하게 (한 메시지 5개 이내)

## 9. 미해결 사항 / 추후 결정

1. **슬랙 워크스페이스**: 디안에 슬랙이 이미 있는지? 없으면 도입 결정 필요
2. **채널 구조**: `#일반` 하나만 vs 카테고리별 여러 채널?
3. **즉시 알림 기준**:
   - "큰 거래" 기준 금액 (1천만 / 5천만 / 1억?)
   - "오래된 미수금" 기준 (60일 / 90일 / 120일?)
4. **일일 메시지 발송 시각**: 9시 vs 시작 직후 (각자 다름)
5. **AI 코칭 메시지**: 일일에 포함할지 (모닝 브리핑은 CEO 전용이지만 일부 메시지를 직원에게도?)
6. **외부 도구**: Slack 외 다른 도구 (디스코드·텔레그램·이메일) 도 지원?
